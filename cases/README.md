# 案例库（cases/）

> [English](README.en.md) | 简体中文

每一个**已跑通的真实案例**存一张卡片。卡片不是"项目报告"，而是**下一个人能照做复现的配方**：选型 → 设置 → 边界 → 初始化 → 推进 → 验收 → 坑。

本库**不预设案例数量**——它是可无限扩充的容器。下面索引里的条目只是当前已有的部分。

## 一、怎么用（动手前必做）

1. 在下面的索引表里按 **`class` 类型 + 关键词** 找 1~2 张最像的卡片。
2. 读卡片的 **§1 选型卡** 与 **§11 已知坑**——这两节决定你要不要从头试错。
3. 照卡片执行，**只改 §13「复用与差异」列出的项**；其余照抄。
4. **没有命中** → 按 `../SKILL.md` §2 物理判型 + `../references/case-setup-checklist.md` 自行选型；
   跑通后**必须回写一张新卡片**（流程见本文件 §四）。

> 检索优先级：**几何同构 > 物理同类型 > 时间尺度接近**。
> 宁可复用"设备/几何相同但物理不同"的网格，也不要把"物理相同但网格分辨不了"的配方硬搬（见 S1 的教训）。

## 三、卡片约定

### 3.1 文件名与 ID

`<ID>-<英文短名>.md`，例如 `L4-autoclave-acid-leak.md`。ID = **分组前缀 + 两位序号**，序号组内递增、不复用旧号。

前缀不是固定的，按"物理/设备族"自行开组，**开了就在下表登记一行**（不登记 = 校验不过）：

| 前缀 | 含义 | 已有 |
|---|---|---|
| `L` | Liquid leak —— 液体/熔体连续泄漏（VOF 自由液面） | L1–L4 |
| `B` | Blast —— 爆炸 / 激波 / 高压泄放（可压缩瞬态） | B1–B4 |
| `S` | Splashing —— 有限液块喷溅、抛射 | S1–S2 |
| `G` | Gas —— 气体/烟气扩散（组分输运） | G1–G3 |

### 3.2 front matter（7 个键，缺一个校验就报错）

```yaml
id: L4
name: <中文名>
class: vof-free-surface
status: verified          # verified | partial | untested
last_run: 2026-09
keywords: [关键词1, 关键词2]
reuse_of: ""              # 从别的卡改来则填其 ID
```

`status` 是**受控词**，只能用这三个：

| 受控词 | 中文 | 判据 |
|---|---|---|
| `verified` | 实测跑通 | 从搭案例到出结果全程跑完，卡片里的数字是实测的 |
| `partial` | 部分实测 | 主路线跑过，但某些环节/设置仍是推定，或结果受已知缺陷影响 |
| `untested` | 未实测（路线推定） | 一次都没跑；**卡片只写路线、依据、前置检查，不写任何结果数字** |

### 3.3 内容规则

- 数字一律带单位；**未实测的项写"待实测"或"按 X 同构推定"**，不要留空、更不要编。
- 每张卡片的 **§11 已知坑** 只写本案例专属的坑；通用坑在 `../SKILL.md` §10 与 `../references/troubleshooting.md`，不要抄一遍。
- 英文卡片用 `_TEMPLATE.en.md`，`status` 仍取上面三个受控词，文件名规则不变。

## 四、怎么填一张卡（完整流程）

> 目标不是"写文档"，是**让下一个拿到这张卡的人不必重跑你踩过的弯路**。

### 第 0 步 · 先判断该不该建新卡

| 你的情况 | 做法 |
|---|---|
| 只换了边界数值/物性，几何与网格要求都没变 | **不建新卡**，在原卡 §6/§13 记一行"变体：参数 X 改为 …" |
| 物理同类、几何不同 | 建卡，`reuse_of` 指向最像的那张，正文**只写差异**（L2 就是这么写的） |
| `class` 变了（换主导机制） | 必须建新卡，`reuse_of` 可留空 |
| 几何同构但网格分辨不了特征尺度 | 仍要建卡，`status` 按实际，并在 §3 与 §11 写清分辨极限（S1 是范例） |
| 只是同一算例多跑了几步 | 不建卡，更新原卡 §9 的实测结果 |

### 第 1 步 · 建文件

```bash
cp cases/_TEMPLATE.md cases/<ID>-<短名>.md
```

### 第 2 步 · 填 front matter

7 个键全填；`status` 只能取受控词；`id` 必须与文件名前缀一致。

### 第 3 步 · 填 §1~§13 —— 每节的数据从哪来

这张表比"每节都要填满"有用得多：

| 章节 | 数据来源 | 必须实测 |
|---|---|---|
| §1 选型卡 | 直接抄 journal 里的求解器/模型设置行；单步耗时用 `总时长 ÷ 步数` 从 `.trn` 算 | 是 |
| §2 几何与计算域 | 三维模型或图纸；**写清竖直轴是哪个** | 是 |
| §3 网格 | `/mesh/check` 输出 + 质量报告；"分辨能力"= 特征尺度 ÷ 当地网格尺度（< 7 格即不可用） | 是 |
| §4 材料与相 | 设计资料 / 物性手册，**标注出处** | 否，但必须标来源 |
| §5 模型与求解设置 | journal 原文；松弛因子与格式照抄实际日志，不要按"推荐值"填 | 是 |
| §6 边界条件 | 先 `/define/boundary-conditions/list-zones` 导出 zone 清单，逐条填 ID + 类型 + 值 + **为什么** | 是 |
| §7 初始化与 patch | patch 命令与值 + **t=0 核验结果**（`ΣαV`、域内总质量等） | 是 |
| §8 推进策略 | 时间步序列（含斜坡）、总步数、autosave 间隔、实测磁盘占用 | 是 |
| §9 监控与验收判据 | 基线来源必须写清是**手算 / 文献 / 实测**，并给算式或页码 | 是 |
| §10 后处理与交付 | 口径五要素：单位、起算基准、阈值来源、切片高度、时间窗 | 是 |
| §11 已知坑 | 只写本次调试**新踩**的、通用表里没有的 | — |
| §12 复现入口 | journal 关键片段 / 脚本名 / 完整命令 | 是 |
| §13 复用与差异 | 与 `reuse_of` 那张卡**逐项对比**：可照抄 / 必须改 / 不能照抄 | — |

某一节写不出来，就写"待实测"——**不要用推测把空格填满**，那比空着危害大。

### 第 4 步 · 放素材

脚本、长表格、几何参数放 `cases/assets/<ID>/`，卡片里用**相对路径**引用（如 `assets/L4/mesh.jou`）。
校验脚本会检查这些引用是否真实存在，所以别把素材放在别处又忘了拷进来。

### 第 5 步 · 更新索引

在 **`cases/README.md` 与 `cases/README.en.md` 两张索引表**里各加一行（两份必须一致，校验脚本会比对）。
"一句话配方"写**最关键的 1~2 个设置**，不要复述案例名。

### 第 6 步 · 跑校验

```bash
python ../scripts/check_cases.py
```

零 error 才算通过。它检查：front matter 完整性、`status` / `class` 是否合法、ID 与文件名是否一致、
`reuse_of` 指向是否存在、**索引表与文件是否双向一致**、相对链接与 `assets/` 引用是否存在。

### 第 7 步 · 人的自检

只有一个判据：**一个没见过这个项目的人，能否只凭这张卡把案例跑出来**。

配套三问（答不上就是没写够）：

1. 卡里的网格尺寸 / 边界值，我是**抄的日志**还是**猜的**？
2. 卡里的验收基线，来源写清了吗？评审能不能顺着追到算式或文献？
3. 我这次踩的坑里，哪一条是通用表里没有的？写进 §11 了吗？
