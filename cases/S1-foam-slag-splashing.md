# S1 · 泡沫渣喷溅

> **一句话画像**：泡沫渣破碎 → 十余团渣块/渣滴同时抛出 → 空中飞行 → 落地铺展。与 [S2](S2-tapping-splashing.md) 同一物理族，但**多团注入**且**网格分辨不了液块**。
> **状态**：实测（2026-10）｜**结论**：注入配方（多 register + 牺牲位）**成功**；但液块仅 2.4 格跨 ⇒ **α 场不能定量**，交付只能走亚网格口径。**这是本案例最值钱的教训。**

## 1 选型卡

| 项 | 取值 |
|---|---|
| 物理类型 | 高密度比多相 + 多液块注入（B 类） |
| 求解器 | 压力基 |
| 时间 | 瞬态 |
| 多相 | VOF **隐式**（主相 air / 次相 slag） |
| 湍流 | 层流 |
| 能量 | **开**（渣温 1000 K 以上，用于注入判据） |
| 重力 | 沿 Y = −9.81 m/s² |
| 时间步 | 5e-3 ~ 1e-2 s（按 CFL 与表面张力双约束） |
| 网格量级 | **1,628,493 单元**（四面体，gmsh 生成 → CGNS 导入） |
| 单步耗时 | **64~69 s/步**（8 核；VOF 隐式 + 能量 + 层流） |
| 验收量 | 注入体积、渣块温度场、足迹/覆盖率（**只能给区间**） |

## 2 几何与计算域

- 熔池熔炼设备车间（含炉体，炉体底面在地面上形成**几何洞**）。
- 注入：**12 个球团**，`R = 0.052 ~ 0.072 m` 量级，设计总注入体积 **1.1e-2 m³**。
- 竖直轴 Y；地面为铺展面。

## 3 网格

| 项 | 值 |
|---|---|
| 路线 | gmsh 脚本化 → CGNS → **PyFluent 导入** |
| 单元数 | **1,628,493**（1 cell zone / 3,276,279 faces / 15 zones） |
| 单元类型 | 纯四面体（可验：`4 × ncell = len(c0) + len(c1)`） |
| 当地尺度 | 弹道区 **h ≈ 0.0703 m** |
| ⚠️ 致命项 | 液块 Ø122 mm / 0.0703 m ≈ **2.4 格** ⇒ **物理上不可辨**（α_max 由 1.0 崩到 0.1 → 0.014） |

**开工前 30 秒必做**：

```python
R_min = 5 * h                      # 10 格直径
V_min = 4/3 * pi * R_min**3        # h=0.0703 ⇒ R_min=0.35 m ⇒ V_min=0.18 m³
# 设计 V_inj = 1.1e-2 m³ << 0.18 m³  ⇒ 差 16 倍，该网格算不了这个案例
```

| zone | 类型 | 说明 |

## 7 初始化与 patch

### 7.1 多 register 必须**一次调用合传**

逐个 `calculate_patch` **不累积**：实测 12 团只生效 3 团、注入量只有设计值的 **24.1%**，而 TUI 每次都打印正确的 `N cells marked`、**不报任何错**。

```python
# ❌ for reg in regs: calculate_patch(registers=[reg], ...)   → 只有少数生效
# ✅ calculate_patch(registers=regs_all, ...)                 → 93.6%
```

诊断范式：**把亏空在时间轴上切开**——patch 后 0 / 1 / 2 步各存一帧。三帧完全一致 ⇒ 缺陷在 patch 时刻；只有第 1 帧对 ⇒ 缺陷在求解器首步。

### 7.2 union 合传的残留缺陷 → **牺牲位**配方

合传后仍**必然漏掉"本次调用中最后一个真正标记到单元的 register"**，表现是**末位团的相分数被涂抹**（球内 α ∈ [0.43, 0.999]、球外 935 个单元被涂值），而**温度 patch 完全正常**。分组合传只会多漏（每组漏一个）。

修法（实测机器精度通过）：

1. 在 case 里预置一个**很小的 register**（`zz_sac0`，R = 0.030 m、**118 个单元**），球心放在 `blob_01` 球心 ⇒ 完全被包住；
2. **写 case → 另起会话读回**，让它真正生效（会话内新建的 register 不参与标记，0 单元的新 register 会被直接忽略）；
3. `calculate_patch` 时把 `blob_01..blob_05` + `zz_sac0` **一次合传，牺牲位放列表末位**。

结果：`ΣαV = 1.121476e-02 m³`（与离线预测相对偏差 **3.1e-16**）、五团 αmean 全 **1.0000**、α>0 单元 **12349 = T>1000K 单元数**、球外溢出 **0**。

### 7.3 三条核验判据（只看总量会漏"糊了一团但总量守恒"）

1. `ΣαV` ≈ 离线 `ΣV(标记单元)`；
2. **逐团 αmean 是否全为 1.0000**；
3. `α>0` 单元数是否等于 `T>1000K` 单元数。

> 这个"t=0 存盘 + 离线核验"是最便宜的把关——它把 4.3 h 的长跑救回来了。

### 7.4 register 的单元量化

`sphere(inside=True)` 按**单元形心落格**标记。当 R 与 h 同量级时标记数剧烈抖动（实测 12 个球里 **2 个标记 0 个单元**、单个体积误差 −100%~+69%）。

- 先离线预演（`dist(centroid, center) <= R`），把球心**吸附到最近单元形心**，取 `2R/h ≳ 1.7`；
- 跑完**回读 Fluent 的 `N cells marked`** 与离线预测**逐团比对**；
- **报"注入体积"要报量化值 `ΣV_cell(标记单元)`**，不是解析式 `4/3πR³`。

## 8 推进策略

- 分段长跑：每 50 步一个 autosave 帧（`S1v2_auto-1-00050.dat.h5`，~275 MB），600 步约 **3.3 GB**（**case 只写一次 ~43 MB，别按帧数乘**）。
- **★ 长跑脚本原样沿用交付 case 内的 `auto_save`**（只读回、不修改）⇒ 本机这一跑 ≡ 用户点运行的那一跑，顺带验证了交付 case 的 auto_save 是否真的写得出。
- 但必须加"第一块硬检 + 兜底"：第一块结束后比对 `glob(AUTO_ROOT*)` 前后集合，没新增就立刻 `write(case-data)` 自建 checkpoint。
- 步时随运行时间缓慢下降（3435 s → 3212 s / 50 步）；**ETA 用最近一个完整块的均值**，别用前几步外推（曾估 84 s/步，实际 64 s/步）。

## 9 监控与验收判据

| 判据 | 标准 | 说明 |
|---|---|---|
| 注入体积 | `ΣαV` = 离线 `ΣV(标记单元)` | §7.3 |

## 10 后处理与交付

- **离线 h5**（VOF 案例槽位语义与单相**完全不同**，见 §11），不启 Fluent。
- 足迹图：地面网格分辨率**极不均匀**，必须按**真实面元**渲染，不能先插值成均匀网格再画。
- 粒子化：用**面邻接连通域**并过滤单胞碎屑。
- **交付形态：可移植 `.wbpj` 工程**（"拷到大内存机 → 双击 → 点运行"），不是本机结果。三条硬要求：
  1. 素材 = patch 后并**离线核验 PASS** 的 `S1v2_t0.{cas,dat}.h5`；
  2. `dat` 必须挂 **`ContainerAssociations: ["Solution"]`** + 系统属性 `"Start from available data": "True"`（只把 dat 拷进目录**不算**，那只是搭便车的散文件）；
  3. 交付说明里明确"**更新 / 双击 Solution**"，别让用户走 `Setup`（只会读到 case，看到 α 全 0 的冷态）。

## 11 已知坑（本案例专属）

| 现象 | 根因 | 处理 |
|---|---|---|
| **液块 α 在 0.1 s 内由 1.0 崩到 0.1** | 液块仅 **2.4 格**跨，网格根本分辨不了 | 重新加密（沿**弹道走廊** Box 场，不要 Distance 场）；或改"等效雾团"并标注；或走亚网格口径 |
| `/file/import/cgns/mesh` 崩在 `Importing` 之后（无栈、无 `Opening library` 行） | **是 `fluent.exe -i journal` 这条启动路径坏了，不是 CGNS 文件坏** | CGNS 导入一律走 **PyFluent + 重试**（241k 与 1.63M 两版都是首次即成） |
| 判"导入成功"被误判 | 看了 exit code 或"无 Fatal failure" | **只认日志里的 `1 cell zone, N face zones`** |
| **多 register 逐个 patch，注入量只有 24%** | 逐个调用不累积 | §7.1 一次合传 |
| **末位团相分数被涂抹**（球内 α 不足 1、球外被涂） | union 合传的固有缺陷 | §7.2 牺牲位 |
| 离线读 `results/1/phase-2` 读到的不是次相 | VOF 下槽位整体挪位：`phase-1` = 混合场、`phase-2` = **主相**、`phase-3` = 次相 | **用密度/粘度的常数值反查**是哪一相，别按"phase-2 就是次相" |
| 离线复算体积对不上 | 面→单元映射错 | `ΣV` 必须与 `/mesh/check` 自报 `total volume` 吻合（实测 rel **5.5e-8**） |
| 用户点运行后看到 α 全 0 | 走的是 `Setup` 入口，或 dat 没挂 Solution 容器 | §10 三条硬要求 |

## 13 复用与差异

- **可以直接照抄的**：多 register 合传 + 牺牲位、t=0 核验三条判据、CGNS 走 PyFluent、可移植 wbpj、VOF h5 槽位语义。
- **必须改的**：球团数量/半径/位置、网格尺度（**先算能否分辨**）、次相物性、autosave 间隔。
- **不能照抄的**：**"设备复用 = 网格可复用"**。同一台设备的加密盒是**为某种物理形态**打的（L1 为地面薄膜、S1 为空中团块），物理形态变了必须重算。
