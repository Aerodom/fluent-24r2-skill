# 版本兼容性：什么算"已验证"，什么必须重测

> **一句话**：本 skill 的全部结论只在 **ANSYS Fluent 2024R2（v242）/ Windows** 上实测过。
> 换到任何其他版本，**把 §2 的每一条命令都当作未验证**，用 P2 的探针 journal 逐条确认后再信。

## 1 已验证组合（可以照做）

| 组件 | 版本 | 验证程度 | 备注 |
|---|---|---|---|
| Fluent 求解器 | 2024R2 / v242, `3ddp` 与 `2ddp` | 实测跑通 | 全部 journal 命令、TUI 提示序列、autosave 续算均在此版本验证 |
| 操作系统 | Windows 10/11 x64 | 实测跑通 | 启动形态、进程树、`.trk`/`.trn` 行为与 Linux 不同 |
| PyFluent | 0.42.1 | 部分实测 | 6 核 `wta` 崩溃仅在此版本复现；见 `pyfluent-vof-sputtering.md` |
| Fluent Meshing（Watertight） | 2024R2 | 部分实测 | 面板名与工作流顺序按此版本记录 |
| gmsh（Python API） | 4.x | 部分实测 | **只验证了"出几何（STEP）"**；它写出的 `.msh` 在本机导入即 SIGSEGV（见 `troubleshooting.md` K 类） |
| HDF5 读取（h5py） | 3.8+ | 实测跑通 | 读 `.cas.h5` / `.dat.h5` 的结构路径按此版本核对 |

## 2 换版本时"最可能变"的六处，以及怎么在 10 分钟内验出来

按**改动概率 × 破坏程度**排序。每一条都给了探针判据 —— 不要凭记忆判断"应该没变"。

| # | 易变点 | 为什么会变 | 探针判据（P2 手法） |
|---|---|---|---|
| 1 | **TUI 命令名与交互提示序列** | Ansys 每两个版本清理一批旧命令；交互式提示的问句措辞也常改，改了就**吃行**导致后续命令错位 | 把命令逐条粘进 `-g` 会话，看是否回 `invalid command`；对每条交互命令先跑一次**只到提示为止**的探针，把实际问句抄下来 |
| 2 | **`.h5` 内部结构路径**（`meshes/`、`fields/`、`SV_*` 语义） | 存储布局随版本演进，键名大小写/层级会调整 | 离线读一次：`h5py.File(...).keys()` 打全树，与 `offline-h5-postprocessing.md` §2 的路径表逐项对照，缺项就停 |
| 3 | **`.wbpj` 模板名与 `DisplayText` 写法** | Workbench 模板随版本重命名 | 生成最小 `.wbpj` 后**无头回读**一次（`SKILL.md` §8 第 4 条），回读不出图就是模板名错 |
| 4 | **边界条件类型码 / zone 命名** | 网格导出端（Meshing、gmsh、CGNS）命名策略不同 | `P2` 的 `N cell zone, M face zones` 行 + zone 清单（ID/类型）与卡片对比 |
| 5 | **求解器默认值**（离散格式、亚松弛、Courant） | 新版本常改默认 | 显式写出每一项，不依赖默认；试跑第 1 步的 `Courant` 与残差量级与卡片比对 |
| 6 | **PyFluent API**（`session.tui` / `field_info` / settings 树） | Python 层迭代比 TUI 快 | `python -c "import ansys.fluent.core as p; print(p.__version__)"`，与上表比对；差异大就退回纯 journal 驱动（§4.1 形态 A） |

## 3 版本策略（写死，避免每次重新讨论）

1. **只承诺 2024R2**。其他版本能跑通是运气，不是契约；`description` 与 README 不得写成"适用于任意版本"。
2. **升版本时先跑冒烟测试**：`tests/smoke/` 下的最小算例（2D 通道层流，有解析解）就是干这个用的 —— 它能在几分钟内同时验证"网格读取 / journal 命令 / 求解 / 离线读数"四层，比直接上真案例便宜两个数量级。
3. **卡片只在实测版本上标 `verified`**。在 2025R1 上跑通不等于原卡升级，应在卡片里新增一行 `verified_on: 2025R1`，而不是改旧结论。
4. **不要为了让新版本跑通去改旧卡片的数字**。旧数字是旧版本的实测记录，改了就等于伪造实测。

## 4 与 `references/` 其他文档的关系

- `tui-commands.md` 是**命令字典**，版本一变最先失效的就是它 → 它的每条命令都应有"探针验证"的痕迹；
- `troubleshooting.md` 的 H 类（栅格化）与版本无关，可以放心复用；
- `meshing-routes.md` 的三个"假崩溃"里，CGNS 那条**与 PATH 有关、与版本无关**，换版本仍然适用。
